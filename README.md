## Язык программирования

Разработанный язык программирования представляет собой минималистичный диалект **Lisp** с поддержкой рекурсивных функций, глобальных и локальных переменных, арифметических операций, условных ветвлений и асинхронных прерываний (ибо того требует вариант).

### Синтаксис

```ebnf
program     = expression ;

expression  = number | string | name | list ;

list        = "(" , form , ")" ;

form        = setq | defun | definterrupt | progn | if
            | aref | aset | io | unary | binary | call ;

setq        = "setq" , name , expression ;
defun       = "defun" , name , "(" , { name } , ")" , expression ;
definterrupt= "definterrupt" , name , "(" , ")" , expression ;
progn       = "progn" , { expression } ;
if          = "if" , expression , expression , expression ;

aref        = "aref" , expression , expression ;
aset        = "aset" , expression , expression , expression ;

io          = "in" , "0"
            | "out" , "1" , expression
            | "print" , expression
            | "ei" | "di" ;

unary       = ( "not" | "inc" | "dec" ) , expression ;

binary      = ( "+" | "*" ) , expression , expression , { expression }
            | ( "-" | "/" | "%" | "and" | "or" | "xor"
              | "lsl" | "lsr" | "<<" | ">>" ) , expression , expression
            | ( "=" | "!=" | "<" | "<=" | ">" | ">=" ) , expression , expression ;

call        = name , { expression } ;

number      = [ "-" ] , digit , { digit } ;
string      = '"' , { ascii-char - '"' } , '"' ;
name        = letter , { letter | digit | "_" } ;
comment     = ";" , { character - newline } , newline ;
```

В грамматике `ascii-char` — символ ASCII. Сравнение возвращает `1` или `0`. В условии `if` транслятор может использовать результат сравнения напрямую для ветвления. Для других выражений условие истинно, если значение отлично от нуля.

### Семантика
* **Стратегия вычислений:** аппликативная, то бишь операнды и аргументы вычисляются слева направо, а аргументы до передачи управления функции.

* **Области видимости.** Глобальные переменные хранятся в статической памяти данных. При первом `setq` транслятор выделяет переменной слово и записывает её адрес в `symbol_table`. Аргументы `defun` размещаются в регистрах и затеняют одноимённые глобальные переменные. Внутри функции доступны её аргументы и уже известные транслятору глобальные переменные. Обработчик прерывания не захватывает аргументы окружающей функции.

* **Значения.** Во время выполнения значение занимает одно 32-битное слово без тега типа. Строковый литерал даёт адрес Паскаль-строки в памяти данных. Все формы языка можно использовать как выражения. Например, `(print (setq x 65))` напечатает `A`, а `(setq x (if (= 1 x) 2 3))` присвоит результат выбранной ветви. Эти правила проверяются в [expressions.yml](tests/golden/expressions.yml). <br>
`ei`, `di`, `defun`, `definterrupt` и пустой `(progn)` дают `0`. Если результат такой формы нигде не используется, транслятор не добавляет инструкцию для его загрузки. Непустой `progn` даёт значение последней формы, а `if` — значение выбранной ветви.

* **Печать.** `print` и `out` передают одно 32-битное значение в порт вывода. Симулятор отображает печатные коды ASCII и перевод строки как символы, остальные коды — в шестнадцатеричной записи с префиксом `\x`. Например, `(out 1 65)` выводит `A`. Для вывода строки функция на Lisp читает её символы через `aref` и отправляет их в порт по одному.

* **Рекурсия:** поддерживается в полном объёме. Самовызов в хвостовой позиции транслятор превращает в переход на начало функции, поэтому циклы по типу `(defun wait () (wait))` работают бесконечно и не расходуют стек, что очень круто и прикольно.

### Литералы

| Вид | Пример | Где размещается |
|-----|--------|-----------------|
| Целое число от 0 до 65535 | `42` | Непосредственно в команде `LDI` |
| Отрицательное или большое число | `-1`, `70000` | Собирается в регистре парой `LDI` + `LSL` + `OR` |
| Строка | `"La-li-lu-le-lo"` | Сегмент данных, формат Паскаль-строки |

## Организация памяти

Модель памяти процессора построена по принципу **фон Неймановской архитектуры** (или Принстонской, кому как приятнее), то бишь:
* Единое адресное пространство размером **16384 байта**, то есть 4096 32-битных слов.

* Адресация байтовая: машинное слово занимает 4 последовательных байта, все обращения выровнены по границе слова, `PC` увеличивается на 4.
* **Разделение адресного пространства:**

```text
       Единая память (4096 слов)
+--------------------------------------+
| 0000        : JMP _start             |  вектор сброса
| 0004        : JMP обработчик / IRET  |  вектор прерывания
| 0008        : начало программы       |
|    ...                               |  .text, тела функций и обработчиков
| 3996                                 |
+--------------------------------------+
| 4000        : переменная / строка    |  .data
|    ...                               |  глобальные переменные и Паскаль-строки
| 12396                                |
+--------------------------------------+
| 12400                                |  .stack, растёт вниз
|    ...                               |
| 16380       : вершина стека SP.      |
+--------------------------------------+
```

Адреса процессора байтовые. Память доступна командами чтения и записи целого слова, поэтому адрес слова должен быть кратен 4 (!!!!).

* Сегмент кода: `0x0000..0x0F9F`, 1000 команд.
* Сегмент данных: `0x0FA0..0x306F`, 2100 слов.
* Стек: `0x3070..0x3FFF`, `SP` инициализируется адресом 16380 и растёт вниз с шагом 4.

Транслятор проверяет, что код не вышел за адрес 4000, а данные — за адрес 12400, и отказывается собирать программу, если сегменты пересекаются. Модель процессора следит за `SP` и останавливается с проверкой при переполнении или опустошении стека.

### Работа с данными

1. **Литералы.** Число, помещающееся в 16 бит, попадает прямо в поле команды `LDI`, непосредственная адресация. Число, больше 16 бит, собирается в регистре в два приёма путём отдельной загрузки старшей и младшей части, потому что поле команды физически меньше машинного слова. В статическую память числовые литералы не выносятся.

2. **Константы.** В контесте моего варика такого понятия константы в языке нет, любое именованное значение — это переменная.
3. **Переменные.** Глобальные переменные живут в сегменте данных. При первом `setq` транслятор выделяет одно слово, начиная с байтового адреса 4000 с шагом 4. Обращение идёт парой `LDI` + `LD`/`ST`. Аргументам функции выделяются регистры. При вызове другой функции активные регистры временно сохраняются в стеке.
4. **Строки.** Строковый литерал размещается в сегменте данных в формате Паскаль-строки: первое слово — длина, далее по одному ASCII коду на машинное слово. Выражение со строкой возвращает адрес её начала, то есть указатель. Строки размещаются подряд по мере встречи в тексте программы. Работа со строками ведётся функциями на самом языке через команды `aref` и `aset`.<br>Поскольку адресация байтовая, а элемент массива занимает слово, `aref` и `aset` умножают индекс на 4 сдвигом влево на два разряда.
5. **Инструкции.** Одна инструкция — одно машинное слово, то бишь 4 байта. Программа начинается с таблицы векторов из двух слов, далее идёт дефолтный код.
6. **Процедуры.** Тело функции размещается в сегменте кода по месту объявления, транслятор обходит его командой `JMP`. Вызов сохраняет адрес возврата в стек командой `CALL`. Перед вызовом активные регистры сохраняются в стек, после возврата восстанавливаются. Хвостовой самовызов компилируется в `JMP` и наш стек не трогает.
7. **Прерывания.** Обработчик размещается в сегменте кода, а по адресу 4 ставится переход на него. Если обработчик не объявлен, по адресу 4 стоит `IRET`. `PC` и `PS` сохраняются аппаратно. Для обработчика без вызовов транслятор генерирует `PUSH`/`POP` для регистров, упомянутых в его машинном коде, кроме `R0`. При наличии вызова сохраняется весь диапазон `R1`–`R10`, поскольку вызванная функция может менять любой регистр из этого набора.

### Распределение регистров

Регистры `R1`–`R10` используются как стек вычислений. Каждое промежуточное значение занимает очередной свободный регистр и освобождается после использования. Первые n регистров заняты аргументами текущей функции.

Транслятор сообщает об ошибке, если одновременно требуется больше регистров, чем доступно. Предел зависит от числа аргументов функции и одновременно используемых промежуточных значений. Временные значения сверх этого предела транслятор в память не выгружает.

## Система команд

Процессор реализован по принципам архитектуры **RISC** со Register-To-Register ISA. Ключевые приколы:
* Фиксированная длина инструкций, а если быть точнее, то **4 байта**.
* Преобразовани данных происходит целиком и полностью внутри регистров.
* Обычная загрузка и сохранение данных выполняются командами `LD` и `ST`. Стековые команды `PUSH`, `POP`, `CALL`, `RET` и `IRET` обращаются к памяти через `SP`.
* Регистровый файл содержит 16 регистров (`R0`–`R15`). `R0` всегда содержит ноль. Специальные регистры `PC`, `SP`, `IR` и `PS` показаны отдельно на схеме. Поле `DataPath.cr` в коде соответствует `IR`.

### Кодирование инструкций

Все команды занимают ровно одно 32-битное слово. Используются два формата:

```text
Регистровый формат (три регистра)
 31      24 23   20 19   16 15   12 11            0
+----------+-------+-------+-------+---------------+
|  opcode  |  Rd   |  Rs1  |  Rs2  |   не исп.     |
+----------+-------+-------+-------+---------------+
     8         4       4       4          12

Формат с непосредственным операндом
 31      24 23   20 19   16 15                    0
+----------+-------+-------+-----------------------+
|  opcode  |  Rd   |  Rs1  |      immediate        |
+----------+-------+-------+-----------------------+
     8         4       4              16
```

Первый формат применяется к трёхрегистровым операциям АЛУ (`ADD`, `SUB`, `MUL`, `DIV`, `MOD`, `AND`, `OR`, `XOR`, `LSL`, `LSR`), второй — ко всем остальным командам. Поле `immediate` хранит константу, адрес перехода, смещение при обращении в память или номер порта.

Примеры:

```text
0x04123000   ADD R1, R2, R3      opcode=04, Rd=1, Rs1=2, Rs2=3
0x0110002A   LDI R1, 42          opcode=01, Rd=1, imm=0x002A
0x02120004   LD  R1, R2, 4       opcode=02, Rd=1, Rs1=2, imm=4
0x1C100001   OUT 1, R1           opcode=1C, Rd=1, imm=1 (номер порта)
0x12000044   JMP 68              opcode=12, imm=0x0044 (байтовый адрес)
```

### Набор инструкций и количество тактов

Полный цикл команды проходит через `T0 Fetch`, `T1 Decode`, `T2 Execute` и, при необходимости, `T3 Mem/WB`. Из `T1` команда `HLT` сразу останавливает процессор. Во время обращения к памяти CU удерживает текущий шаг до готовности. Попадание при чтении занимает 1 такт, обращение к RAM — 10 тактов с учётом такта запуска. `LD` и `POP` записывают результат в регистровый файл на такте готовности чтения.

| Команда | Действие | Все чтения попали в кеш | Промах выборки | Промах выборки и одного чтения данных |
|---------|----------|-----------:|---------------:|------------------------:|
| `LDI Rd, imm` | `imm -> Rd` | 3 | 12 | — |
| `ADD/SUB/MUL/DIV/MOD Rd, Rs1, Rs2` | арифметика | 3 | 12 | — |
| `AND/OR/XOR/LSL/LSR Rd, Rs1, Rs2` | логика и сдвиги | 3 | 12 | — |
| `NOT Rd, Rs1` | `~Rs1 -> Rd` | 3 | 12 | — |
| `INC/DEC Rd` | `Rd ± 1 -> Rd` | 3 | 12 | — |
| `CMP Rd, Rs1` | `Rd - Rs1 -> NZVC` | 3 | 12 | — |
| `JMP/JZ/JNZ/JL/JGE addr` | переход | 3 | 12 | — |
| `IN Rd, port` | порт `-> Rd` | 3 | 12 | — |
| `OUT port, Rd` | `Rd ->` порт | 3 | 12 | — |
| `EI` / `DI` | разрешить/запретить прерывания | 3 | 12 | — |
| `LD Rd, Rs1, off` | `Mem[Rs1+off] -> Rd` | 4 | 13 | 22 |
| `POP Rd` | снять со стека | 4 | 13 | 22 |
| `RET` | возврат из функции | 4 | 13 | 22 |
| `ST Rd, Rs1, off` | `Rd -> Mem[Rs1+off]` | 13 | 22 | — |
| `PUSH Rd` | положить в стек | 13 | 22 | — |
| `CALL addr` | вызов функции | 13 | 22 | — |
| `IRET` | возврат из прерывания | 5 | 14 | 23 |
| `HLT` | останов | 2 | 11 | — |

Каждый промах чтения добавляет 9 тактов к варианту с попаданием. Например, `LD` при попадании выборки и промахе данных занимает 13 тактов. Сквозная запись всегда стоит 10 тактов. Аппаратный вход в прерывание состоит из двух последовательных записей (`T4 SAVE PC`, `T4 SAVE PS`) и занимает 20 тактов. Выборка инструкции вектора начинается после этих двух записей.

Для `IRET` общее время равно времени выборки плюс 2 такта на декодирование и исполнение, плюс время чтения `PS` и `PC`. В зависимости от числа промахов среди трёх чтений команда занимает 5, 14, 23 или 32 такта.

### Ввод-вывод

Тут мы имеем **PMIO**: порт `0` — ввод, порт `1` — вывод. Обращение возможно только командами `IN` и `OUT`, номер порта кодируется в поле `immediate`.

Внешнее устройство хранит последнее принятое значение в `In_Reg` и выставляет `dev_signal` при получении новых данных. Текстовый ввод даёт коды ASCII, расписание JSON также допускает целые машинные слова. `IN` читает содержимое `In_Reg` и снимает `dev_signal`. Регистр сохраняет последнее значение, начальное значение равно нулю. Если новое значение приходит при ещё поднятом `dev_signal`, оно затирает прежнее, и модель пишет об этом в журнал.

### Система прерываний

В терминах варианта `trap` прерывания считаются внутренними. Событие, которое вызывает запрос, приходит асинхронно от внешнего устройства через `dev_signal`. Аппаратная логика формирует `IRQ = dev_signal & IE`, и процессор проверяет его на границе команд, в том числе после завершения ожидающей операции памяти. При входе он запоминает старый `PS`, сбрасывает `IE`, последовательно сохраняет `PC` и старый `PS` в стек и загружает в `PC` байтовый адрес вектора `0x0004`. По этому адресу лежит `JMP` на обработчик или `IRET`, если обработчик отсутствует.

Вложенные прерывания запрещены, пока установлен `int_active`. Если новый байт пришёл после `IN`, запрос остаётся активен и обслуживается после `IRET`, когда восстановленный `PS` разрешает прерывания. Если новый байт пришёл до `IN`, он затирает непрочитанный. Оба случая есть в golden-тесте `interrupt_burst`.


## Транслятор

Консольное приложение `translator.py` реализует двухпроходный компилятор.

**Интерфейс командной строки:**
```bash
python3 src/translator.py -i <input.lisp> -o <target.bin> [-l <listing.txt>]
```

| Ключ | Назначение |
|------|------------|
| `-i`, `--input` | Исходный файл на разработанном языке |
| `-o`, `--output` | Выходной бинарный файл с машинным кодом |
| `-l`, `--listing` | Отладочный листинг (необязательно) |

**Этапы трансляции:**
1. **Токенизация**, во время которого идёт разбиение текста на токены с сохранением строковых литералов и удалением комментариев на `;`.
2. **Парсинг** с рекурсивным спуском и с построением вложенного дерева s-выражений.
3. **Сбор сигнатур** с предварительным обходом дерева, дабы функция была видна в кода до её объявления, ну и чтоб избежать дублирования названий функций.
4. **Семантический анализ**, где я проверяю зарезервированные имена переменных и функций, валидация портов и лимита регистров.

5. **Генерация кода** с рекурсивным обходом, динамическое выделение регистров `R1,R10` и трансляция в RISC-инструкции. Тело функции компилируется в хвостовой позиции, самовызов превращается в переход.
6. **Компоновка (Линковка)**, где происходит двухпроходное разрешение символических меток в числовые адреса памяти, а также построение таблицы векторов.
7. **Сериализация:** запись 32-битного дампа памяти в бинарник через `struct.pack` и генерация отладочного листинга вида `<адрес> - <хекскод> - <мнемоника>`.


## Модель процессора

Консольное приложение `machine.py` реализует потактовый симулятор процессора с жесткой логикой управления Hardwired Control Unit и кэш-памятью.

**Интерфейс командной строки:**
```bash
python3 src/machine.py -c <code.bin> [-i <input.txt>] [-t <max_ticks>] [--no-cache]
```

| Ключ | Назначение |
|------|------------|
| `-c`, `--code` | Бинарный файл с машинным кодом |
| `-i`, `--input` | Текст ASCII (пробелы и переводы строк сохраняются) или файл `.json` со списком пар `[такт, значение]` |
| `-t`, `--ticks` | Общий лимит тактов. По умолчанию 20 000 тактов после последнего события ввода или 5000 от старта, если ввода нет |
| `-l`, `--listing` | Листинг трансляции: в журнал попадут строки исходника |
| `--no-cache` | Отключить кеш, каждое обращение в память стоит 10 тактов |

Текстовый файл подаёт первый символ на такте 50, остальные с интервалом 1500 тактов. Для числовых токенов и более точного расписания стоит юзать структурные файлы формата .json. В обеих режимах устройство хранит только один непрочитанный токен. Для длительных алгоритмов лучше увеличивать общий лимит, например `-t 600000` при запуске теста на коллатц на огромном числе.

Редактируемый исходник всех трёх схем — [lab4_schemes_memory_request.drawio](scheme/lab4_schemes_memory_request.drawio). SVG ниже экспортированы из этого файла. Одноимённые метки на разнесённых концах обозначают общий сигнал. Пунктиром показаны управляющие сигналы и сигналы готовности.

### DataPath

![DataPath](scheme/DataPath.drawio.svg)

| Элемент | Назначение |
|---------|------------|
| `Register File` | 16 регистров `R0..R15`, `R0` заземлён на ноль |
| `PC` | Счётчик команд, увеличивается выделенным сумматором `+4`, поскольку адресация байтовая |
| `SP` | Указатель стека, меняется на `−4`, `+4` или `+8` при возврате из прерывания |
| `Stack address` | Выбирает адрес `SP`, `SP + 4` или `SP + 8` для операций со стеком |
| `IR` | Регистр инструкции. Опкод `IR[31:24]` идёт в CU. DataPath использует индексы `Rd`, `Rs1` и `Rs2` и расширяет `imm16` нулями до `imm32` |
| `SR` (`PS`) | Регистр состояния `NZVC`, `IE` |
| `ALU` | Арифметика, логика и сдвиги, выставляет флаги |
| `Запрос памяти` | Фиксирует текущий адрес, вид операции и данные записи. До отправки проверяется полный адрес. `addr_ok` учитывает перенос из `ALU_Addr[32:0]`, диапазон RAM и выравнивание |
| `Cache` | Кеш между процессором и общей однопортовой RAM. Через него идут команды и данные |
| `RAM` | Единая память: 4096 32-битных слов, или 16 КиБ |
| `In_Reg` / `Out_Reg` | Регистры данных портов 0 и 1 |

На борту имеются следующие управляющие сигналы: `latch_pc`, `sel_pc`, `addr_sel`, `mem_read`, `mem_write`, `mem_data_sel`, `latch_ir`, `reg_write`, `reg_data_sel`, `read_a_sel`, `read_b_sel`, `alu_op`, `alu_src_sel`, `sp_sel`, `sp_latch`, `stack_addr_sel`, `sr_sel`, `sr_write`, `IE_we`, `IE_in`, `port_out_write`. <br>В ControlUnit поступают `opcode` из `IR`, флаги из `SR`, `dev_signal` от порта 0 и `ready` от кеша. Шина `R_data` подаёт слово в `IR` при выборке, в Writeback MUX при `LD`/`POP`, в тракт `PC` при `RET`/`IRET` и во временный `saved_ps` при первом чтении `IRET`. При завершении `IRET` CU восстанавливает `SR` из `saved_ps`.

### ControlUnit

![ControlUnit](scheme/ControlUnit.drawio.svg)

Устройство управления построено на жёсткой логике. Опкод из `IR[31:24]` поступает в дешифратор управления, логику следующего шага и схему проверки ветвлений. Схема ветвлений получает также флаги `NZVC` и передаёт `branch_taken` в дешифратор для выбора входа `PC MUX`. Например, для `LD` в `T2` вычисляется адрес, а в `T3` запускается чтение и по готовности выполняется запись в регистр.

На схеме `start` обозначает импульс запуска (`mem_read` или `mem_write`). CU разрешает его на шаге обращения при `addr_ok = 1` и `pending_mem = 0`. На такте запуска без ответа текущий шаг сохраняет логика переходов. На следующих тактах ожидания его удерживает `Step MUX`. Если IRQ принят до выборки, активным шагом становится `T4 Save PC`. `done` завершает активный запрос при `ready = 1`. При попадании чтения `start` и `done` возможны на одном такте. Мультиплексор `saved_ps` выбирает `SR_Out` при входе в прерывание и `R_data` при первом чтении `IRET`.

В симуляторе переходы автомата и выбор сигналов заданы ветвлениями по состоянию и опкоду. `ControlUnit` выбирает действие и момент его выполнения, а `DataPath` вычисляет адрес для `LD/ST`, выполняет арифметику, пишет регистры и обслуживает порты. Для вычисления адреса запись `NZVC` отключена.

| Шаг | Что происходит |
|-----|----------------|
| `T0 Fetch` | Адрес из `PC` идёт в кеш, слово защёлкивается в `IR` |
| `T1 Decode` | Декодер разбирает поля команды |
| `T2 Execute` | Работа АЛУ, регистрового файла, портов, расчёт адреса |
| `T3 Mem/WB` | Обращение в память; после чтения `LD` или `POP` результат записывается в регистр на такте готовности |
| `T4 Save PC`, `T4 Save PS` | Две последовательные записи в стек при входе в прерывание |
| `T3 IRET PC` | Второе чтение для `IRET`. По его завершении восстанавливаются `PC`, ранее считанный `PS` и указатель стека |

Обычные команды без обращения к памяти на этапе исполнения, например `LDI` и `ADD`, завершаются на `T2`. При входе в прерывание сначала в стек записывается `PC`, затем `PS`, после чего `PC` получает адрес вектора `4`. CU сохраняет прежний `PS` во временном `saved_ps` до сброса `IE`. `IRET` начинает чтение `PS` в `T3` и читает `PC` в `T3 IRET PC`.

**Ожидание памяти.** В Python роль незавершённого запроса выполняют сохранённые `mem_addr`, `mem_value`, `mem_op` и счётчик `stall_ticks`. Промежуточные такты отмечены `STALL`, последний такт долгого обращения — `MEM READY`. На нём завершается чтение или запись. `LD` и `POP` защёлкивают `R_data` в регистровом файле при завершении.

**Прерывание.** Сигнал `IRQ = dev_signal ∧ IE` принимается на границе инструкций при `int_active = 0`. При входе в обработчик CU выставляет `int_active`, при завершении `IRET` сбрасывает. В журнале этому биту соответствует колонка `INT`.

### Флаги регистра состояния

| Бит | Флаг | Смысл |
|-----|------|-------|
| 0 | `C` | Перенос при сложении и инкременте, заём при вычитании, сравнении и декременте, выход произведения за 32 бита при `MUL`, последний вытесненный бит при ненулевом сдвиге. Для остальных операций АЛУ — 0 |
| 1 | `V` | Знаковое переполнение для `ADD`, `SUB`, `CMP`, `INC`, `DEC`. Для остальных операций АЛУ — 0 |
| 2 | `Z` | Младшие 32 бита результата равны нулю |
| 3 | `N` | Старший бит 32-битного результата |
| 5 | `IE` | Прерывания разрешены |

Биты 4 и 6–31 не используются.

### Кеш-память

![Кеш-память](scheme/Cache.drawio.svg)

Кеш прямого отображения хранит **8 строк по 4 слова**, всего 128 байт. В байтовом адресе `addr[31:4]` — номер 16-байтного блока, `addr[6:4]` — индекс строки, `addr[3:2]` — номер слова. Для выровненного 32-битного слова `addr[1:0] = 00`. Тег в модели хранит полный номер блока. В классической схеме для выбранной строки достаточно старшей части `addr[31:7]`, так как индекс строки уже совпадает.

Индекс выбирает одну строку массива. Сигнал `hit` выставляется, когда эта строка действительна (`valid = 1`) и её тег равен входному номеру блока. На схеме первый MUX выбирает блок из массива при попадании или из RAM при заполнении, второй выбирает слово по `word_idx`. В Python при промахе сначала записывается вся строка, затем из неё возвращается нужное слово.

На границе кеша подписаны отдельно `addr`, `W_data`, `mem_read`, `mem_write`, `R_data` и `ready`. `hit` проверяет наличие блока и при чтении определяет выбор `sel_block`. `ready` подтверждает завершение чтения или записи. Схема Cache описывает фиксированную задержку ответа. В Python её отсчитывает CU через `stall_ticks`. При записи всегда обновляется RAM. При попадании обновляется и слово кеша, при промахе строка не выделяется. `R_data` используется только при чтении.

ОЗУ обслуживает один запрос за раз. При промахе чтения оно за 10 тактов возвращает выровненный 16-байтный блок, начиная с адреса `addr & ~0xF`. При записи на тот же порт передаются адрес слова и 32-битное значение. Попадание при чтении занимает 1 такт. Загрузка блока использует пространственную локальность соседних слов.

### Особенности моделирования

Модель потактовая. `tick()` выполняет один такт и может оставить CU в текущем состоянии. При запуске запроса `ControlUnit` фиксирует адрес, тип операции и данные записи, затем отсчитывает задержку через `stall_ticks`. Результат чтения или запись фиксируется один раз на такте готовности. До кеша модель проверяет полный адрес на диапазон RAM и выравнивание по 4 байтам. Например, `0xFFFFFFFC + 4` даёт ошибку адреса. Вход в обработчик и выход из него используют по два обращения через тот же порт памяти.

Журнал пишется на каждый такт и содержит номер такта, шаг цикла, `PC`, машинное слово из регистра команд, мнемонику, `SP`, флаги, состояние кеша, признак работы в прерывании, регистры `R0`–`R15` и фрагмент исходника, если загружен листинг. Ввод и вывод процессора попадают в журнал отдельными событиями.

При генерации транслятор связывает инструкции с выражениями исходника. В листинге фрагмент записывается в той же строке, что и инструкция. Переводы строки выводятся в экранированном виде. Модель читает эти подписи по ключу `-l`.

```text
|  TICK  | STEP      |  PC   | HEX CODE | INSTRUCTION            |   SP   |  NZVC  |   CACHE   | INT  |    R0    R1    R2 ... | SOURCE
|   15   | T2 EXEC   |  12   | 01100FA4 | LDI R1, 4004           | 16380  |  0000  |  HIT (1)  |  -   |     0  4004     0 ... | "Hello, World!"
|   18   | T2 EXEC   |  16   | 01200FA0 | LDI R2, 4000           | 16380  |  0000  |  HIT (1)  |  -   |     0  4004  4000 ... | (setq msg "Hello, World!")
[ТАКТ 206] Процессор вывел в порт 1 символ 'H' (код 72)
[ТАКТ 100] ВУ прислало символ 'A' (ASCII 65), провод IntRq = 1!
[ТАКТ 101] Вход в прерывание: начинаем сохранять PC и PS
[ТАКТ 120] PC и PS сохранены в стек, переход на вектор
```

Колонка `PC` показывает настоящее значение регистра, поэтому на последнем шаге команды он уже указывает на следующую. Мнемоника и исходник относятся к команде, лежащей в регистре команд.

### Влияние кеша на производительность

Замеры делал на одних и тех же бинарниках с кешем и с ключом `--no-cache`. Для программ с вводом первое событие подаётся на такте 200, следующие — с шагом 3000. Подобное расписание позволяет обработать все входяшие токены при разных режимах. Вывод для каждой пары запусков совпадает. Доля попаданий считается по чтениям, без учёта записей.

| Программа | Без кеша | С кешем | Ускорение | Попаданий |
|-----------|---------:|--------:|----------:|----------:|
| `collatz` | 95993 | 48628 | 2.0x | 76% |
| `hello` | 4197 | 1578 | 2.7x | 82% |
| `hello_user_name` | 20189 | 17228 | 1.2x | 94% |
| `linear_filter` | 26971 | 12616 | 2.1x | 72% |
| `double_precision` | 36227 | 18812 | 1.9x | 68% |
| `sort` | 32597 | 24243 | 1.3x | 90% |
| `infix_to_rpn` | 48445 | 36364 | 1.3x | 89% |

Попадания сокращают задержку чтения, но сквозные записи всё равно занимают по 10 тактов. У программ с вводом время ожидания следующего события тоже входит в замер, поэтому высокая доля попаданий сама по себе не гарантирует такого же выигрыша по общему времени.
